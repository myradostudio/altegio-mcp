# altegio-mcp

[MCP](https://modelcontextprotocol.io)-сервер для API онлайн-запису [Altegio](https://alteg.io) — системи запису й керування для салонів, клінік, студій та інших сервісних бізнесів. Із ним ШІ-асистент, наприклад Claude, відповідає на запитання «на що можна записатися, до кого і коли» для філії. А якщо ви прямо це дозволите — створює і скасовує записи.

English: [README.md](README.md)

> **Неофіційний проєкт.** Він не пов’язаний з Altegio і не схвалений цією компанією. «Altegio» — торговельна марка її власника. Ви користуєтеся сервером на власний ризик: запис, створений інструментами запису, займає справжній час у справжньому розкладі.

> **Стан: версія 0.1.0, на живому акаунті Altegio ще не перевірено.** Сервер написано за двома описами OpenAPI, які Altegio публікує на [developer.alteg.io](https://developer.alteg.io): «Online Booking» і «Business Management v1» (обидва версії 1.0.0 станом на 08.10.2026). Усі тести працюють з імітацією HTTP і звіряють кожен запит зі знімком цих описів. Зі справжнім партнерським токеном сервер ще ніхто не запускав. Докладніше — у розділі [Обмеження](#обмеження).

## Для чого він

Бізнеси в Altegio публікують віджет запису, де клієнт обирає послугу, майстра й час. Ті самі кроки доступні партнерам через API. Цей сервер подає їх як інструменти MCP, тож асистент, чат-бот або голосовий агент може провести клієнта через запис у розмові.

Сервер бачить те саме, що й віджет: послуги, майстрів, вільний час і записи, які створив сам. Розкладу, клієнтської бази та фінансів бізнесу він не бачить: ця частина API Altegio потребує токена користувача й до сервера не входить.

Altegio має і власний хмарний [Integrations Hub MCP](https://developer.alteg.io/en/developers/integrations-hub-mcp). Він керує застосунками маркетплейсу в кабінеті розробника. Це інше завдання: він не замінює цей сервер, а цей сервер — його.

## Швидкий старт

Потрібні Node.js 20 або новіший, **партнерський токен** та **ідентифікатор філії**.

- Партнерський токен з’являється в кабінеті розробника Altegio в розділі Account settings → Account details після реєстрації розробником в [Altegio Marketplace](https://app.alteg.io/appstore/developers/1). Див. інструкцію Altegio [How to Get API Keys](https://developer.alteg.io/en/get-api-key).
- Ідентифікатор філії — це номер філії в Altegio. Якщо у вас є лише посилання на віджет на зразок `https://b123.alteg.io`, інструмент `get_booking_form` перетворить ідентифікатор форми `123` на ідентифікатор філії.

> **В npm пакета ще немає.** Доки перший реліз не опубліковано, команди `npx -y @myradostudio/altegio-mcp` нижче не працюватимуть. Запускайте сервер із вихідного коду: `git clone https://github.com/myradostudio/altegio-mcp`, далі `npm install` і `npm run build` у цій теці, а в налаштуваннях нижче вкажіть `"command": "node"` і `"args": ["/абсолютний/шлях/до/altegio-mcp/dist/index.js"]`.

### Claude Desktop

Додайте сервер до `claude_desktop_config.json` (Settings → Developer → Edit Config):

```json
{
  "mcpServers": {
    "altegio": {
      "command": "npx",
      "args": ["-y", "@myradostudio/altegio-mcp"],
      "env": {
        "ALTEGIO_PARTNER_TOKEN": "ваш партнерський токен",
        "ALTEGIO_LOCATION_ID": "ідентифікатор вашої філії"
      }
    }
  }
}
```

Якщо у Windows сервер не запускається, вкажіть `"command": "cmd"` і `"args": ["/c", "npx", "-y", "@myradostudio/altegio-mcp"]`.

### Claude Code

```bash
claude mcp add --transport stdio \
  --env ALTEGIO_PARTNER_TOKEN=ваш-партнерський-токен \
  --env ALTEGIO_LOCATION_ID=ідентифікатор-філії \
  altegio -- npx -y @myradostudio/altegio-mcp
```

### Cursor

Додайте такий самий блок до `~/.cursor/mcp.json` (для всіх проєктів) або `.cursor/mcp.json` (для одного проєкту):

```json
{
  "mcpServers": {
    "altegio": {
      "command": "npx",
      "args": ["-y", "@myradostudio/altegio-mcp"],
      "env": {
        "ALTEGIO_PARTNER_TOKEN": "ваш партнерський токен",
        "ALTEGIO_LOCATION_ID": "ідентифікатор вашої філії"
      }
    }
  }
}
```

Будь-який інший MCP-клієнт, що вміє запускати локальний stdio-сервер, налаштовується так само: запустіть `npx -y @myradostudio/altegio-mcp` зі змінними середовища з таблиці нижче.

Після цього можна запитати, наприклад:

- «Які послуги є в салоні й скільки коштує стрижка?»
- «Хто робить манікюр і коли найближчий вільний час цього тижня?»
- «Чи вільна Олена в суботу о 15:30 на стрижку з фарбуванням?»
- З увімкненими інструментами запису: «Запиши Ірину, +380501234567, на стрижку до Олени в суботу о 15:30».

## Налаштування

Сервер налаштовується лише змінними середовища. Під час запуску він їх перевіряє і, якщо щось не так, завершує роботу з поясненням у stderr.

| Змінна | Обов’язкова | Типове значення | Призначення |
| --- | --- | --- | --- |
| `ALTEGIO_PARTNER_TOKEN` | так | | Партнерський токен вашого кабінету розробника Altegio. Лише сам токен — без `Bearer` і без токена користувача. |
| `ALTEGIO_LOCATION_ID` | ні | | Числовий ідентифікатор філії. Якщо його задано, сервер прив’язано до цієї філії: `location_id` можна не передавати, а виклик з іншою філією буде відхилено. Якщо не задано, кожному інструменту, що працює з філією, потрібен `location_id`. |
| `ALTEGIO_API_URL` | ні | `https://api.alteg.io` | Адреса API. Лише `https://` (звичайний `http://` дозволено тільки для localhost). |
| `ALTEGIO_ALLOW_WRITE` | ні | вимкнено | Значення `1` вмикає інструменти запису. Якщо значення не належить до `1`/`true`/`yes`/`on` чи `0`/`false`/`no`/`off`, сервер не запуститься. |

## Інструменти

Ідентифікатори — числа. Тривалість (`seance_length`, `sum_length`) — у секундах. Ціни — у валюті філії. Час слотів — місцевий час філії; її часовий пояс повертає `get_location`. Сервер повідомляє про це моделі.

### Інструменти читання (доступні завжди)

| Інструмент | Що повертає | Запит до API |
| --- | --- | --- |
| `get_location` | Назву, місто, адресу й часовий пояс філії та чи потрібне підтвердження телефону через SMS | `GET /locations/{location_id}` |
| `get_booking_form` | Налаштування віджета запису за його ідентифікатором, зокрема філію, якій він належить | `GET /bookform/{id}` |
| `list_services` | Послуги, відкриті для онлайн-запису: категорії, діапазон цін, тривалість | `GET /book_services/{location_id}` |
| `list_staff` | Майстрів, відкритих для онлайн-запису; за потреби лише тих, хто надає певні послуги | `GET /book_staff/{location_id}` |
| `list_available_dates` | Дати, на які ще є вільний час, і робочі дати | `GET /book_dates/{location_id}` |
| `list_time_slots` | Вільні слоти майстра (або будь-кого) на дату | `GET /book_times/{location_id}/{team_member_id}/{date}` |
| `get_nearest_time_slots` | Найближчий день із вільним часом у майстра та слоти цього дня | `GET /book_staff_seances/{location_id}/{team_member_id}` |
| `check_booking` | Чи можна записатися просто зараз; якщо ні — причини від Altegio | `POST /book_check/{location_id}` |
| `get_booking` | Запис за ідентифікатором і хешем: час, послуги, майстер, філія | `GET /book_record/{location_id}/{record_id}/{record_hash}` |

Усі шляхи — відносно `https://api.alteg.io/api/v1`.

`check_booking` — єдиний інструмент читання, що надсилає `POST`. Саме так Altegio описує перевірку параметрів запису; за документацією, цей запит нічого не створює і слот не резервує.

`list_services` повертає до 100 послуг за виклик (щонайбільше 500) і підтримує `search`, `category_id`, `limit` та `offset`. Ці чотири параметри сервер застосовує сам до списку, який повернув Altegio: в API немає ні посторінкового виведення, ні текстового пошуку послуг.

### Інструменти запису (лише з `ALTEGIO_ALLOW_WRITE=1`)

| Інструмент | Що робить | Запит до API |
| --- | --- | --- |
| `create_booking` | Створює один візит: одна чи кілька послуг в одного майстра на один час початку | `POST /book_record/{location_id}` |
| `send_phone_confirmation_code` | Просить Altegio надіслати SMS-код на телефон клієнта — для філій, де потрібне підтвердження | `POST /book_code/{location_id}` |
| `cancel_booking` | Видаляє запис за його ідентифікатором і хешем | `DELETE /user/records/{record_id}/{record_hash}` |

`create_booking` повертає `record_id` і `record_hash`. Збережіть обидва: із самим лише партнерським токеном переглянути чи скасувати цей запис можна тільки за ними.

## Модель безпеки

Запис займає час живої людини й може спричинити повідомлення клієнтові, тому сервер навмисно обережний.

- **Без вашого дозволу — тільки читання.** Без `ALTEGIO_ALLOW_WRITE=1` інструменти запису взагалі не реєструються: модель їх не бачить і викликати не може. Окремий тест перевіряє, що інструменти читання надсилають лише `GET` — з єдиним задокументованим винятком, `check_booking`.
- **Одна філія, якщо ви так вирішили.** Коли задано `ALTEGIO_LOCATION_ID`, жоден інструмент, що приймає філію, не працює з іншою, а `get_booking_form` відхиляє форму, яка належить іншій філії. Поза прив’язкою лишається один інструмент: в адресі запиту `cancel_booking` філії немає, тож сервер не може визначити, де цей запис. Йому потрібен хеш запису, а хеш відомий лише для записів, створених через цю саму інтеграцію.
- **Чесні анотації.** Інструменти читання мають `readOnlyHint: true`. `create_booking` і `send_phone_confirmation_code` щось додають і позначені як запис без руйнування даних; `cancel_booking` видаляє запис і має `destructiveHint: true`. Жоден інструмент запису не позначено як ідемпотентний. Чи показувати підтвердження і як саме, вирішує ваш MCP-клієнт; не вимикайте підтвердження кожного виклику для інструментів запису.
- **Сувора перевірка вхідних даних.** Кожен інструмент відхиляє аргументи, яких не знає, тож фільтр, якого в API немає, не буде мовчки проігноровано. `create_booking` вимагає час початку зі зміщенням від UTC — точно так, як його повертає слот, щоб «15:30» не було прочитано в чужому часовому поясі; дату, якої не існує (30 лютого), сервер відхиляє, а не переносить на інший день.
- **Жодних повторів наосліп.** Сервер сам ніколи не повторює запит. Якщо запит на запис завершився без певної відповіді (сплив час очікування, обірвалося з’єднання, шлюз повернув помилку, прийшла відповідь HTTP 429 або відповідь не вдалося прочитати), інструмент повідомляє, що результат невідомий, і пояснює, що робити. Altegio не описує способу зробити запит на створення запису безпечним для повтору, а із самим лише партнерським токеном сервер не може знайти запис без його хеша. Тому чесна порада — попросити бізнес перевірити розклад, перш ніж записувати знову. Список вільних слотів пропонується лише як підказка, а якщо запис був «до будь-якого майстра» — не пропонується зовсім.
- **У межах задокументованої частоти.** Altegio дозволяє 200 запитів за хвилину і 5 за секунду з однієї IP-адреси. Сервер відповідно розподіляє власні запити: короткий сплеск чекає до двох секунд, а далі інструмент не надсилає запит і повідомляє, коли спробувати знову.
- **Токен зберігається лише у вас.** Сервер читає його зі змінної середовища, використовує лише для запитів до `ALTEGIO_API_URL` і ніколи не виводить у stdout чи stderr. Кожну відповідь API сервер очищає від токена ще до того, як щось із неї будує, тож і в результат інструмента він потрапити не може. За перенаправленнями сервер не переходить, тому ні токен, ні телефон клієнта не потраплять на інший хост.
- **Моделі — менше даних.** Інструменти повертають стислі об’єкти без аватарів, оформлення віджета, ідентифікаторів аналітики та біографій у HTML.
- **Жодної телеметрії; дані бізнесу не потрапляють у журнали.** У stderr потрапляють лише повідомлення під час запуску (помилки налаштувань і рядок із режимом роботи) та тип помилки транспорту. Запити й відповіді ніде не записуються.

Двох речей сервер за вас не зробить. По-перше, усе, що повертає інструмент, потрапляє до ШІ-моделі, якою ви користуєтеся, і до її постачальника, а `create_booking` передає через цю модель ім’я й телефон клієнта; зважте, чи прийнятно й чи законно це для даних ваших клієнтів. По-друге, назви послуг і коментарі з Altegio модель отримує без змін, і в них можуть бути чужі інструкції (prompt injection). Це ще одна причина підтверджувати кожен виклик запису власноруч.

## Обмеження

- **Сервер не перевірено на живому акаунті.** Запити звірено з описами OpenAPI, а вони описують структуру даних, а не поведінку. Обробку відповідей і тексти помилок реалізовано за документацією та її прикладами. Зокрема, ще ніхто не підтвердив, які філії відповідають на певний партнерський токен і що відповідає філія, де онлайн-запис вимкнено. З’ясувати це має [жива перевірка](#жива-перевірка); на справжньому акаунті її ще не запускали.
- **Лише партнерський токен.** Усе, що потребує токена користувача, до сервера не входить: список і пошук записів філії, клієнтська база, перенесення запису на інший час (`PUT /book_record`), розклад, продажі й фінанси.
- **`check_booking` і HTTP 404.** Altegio описує 404 і для випадку «майстер не надає цю послугу», і для філії, якої не знайдено. Інструмент повідомляє «записатися не можна» й додає, що ідентифікатори можуть бути хибними.
- **`cancel_booking` залежить від філії.** За документацією Altegio, хеш призначено для видалення запису одразу після створення, а філія може заборонити клієнтам скасовувати записи (`allow_delete_record`). В обох випадках очікуйте відмови.
- **Один візит за виклик.** API приймає кілька візитів в одному запиті; `create_booking` надсилає один — з однією чи кількома послугами.
- **Чого немає:** групових подій, онлайн-оплати й депозитів, додаткових полів запису, карток лояльності й абонементів, відгуків, особистого кабінету клієнта.
- **Чотири місця, де описи суперечать самі собі.** Сервер дотримується того прочитання, яке видається правильним, а тести перелічують кожен випадок, тож виправлення з боку Altegio не залишиться непоміченим:
  - фільтр `datetime` у `list_staff` і `get_nearest_time_slots` оголошено числом, а описано як дату ISO 8601; сервер надсилає текст ISO 8601;
  - у `create_booking` SMS-код (`code`) і зовнішній ідентифікатор (`api_id`) у схемі оголошено числами, а в таблиці полів — рядками; сервер надсилає рядки, щоб код, який починається з 0, не зіпсувався.
- **Списки ідентифікаторів.** `service_ids[]` у трьох методах оголошено масивом, а у двох — рядком. Сервер завжди надсилає повторювані ключі (`service_ids[]=1&service_ids[]=2`). З однією послугою обидва прочитання дають той самий запит; із кількома це треба підтвердити на живому акаунті.
- **`send_phone_confirmation_code` надсилає лише телефон.** Необов’язкове ім’я клієнта не передається, бо в схемі й в описі документації це поле названо по-різному.
- **Частоту запитів сервер рахує лише для себе.** Altegio рахує запити за IP-адресою. Інші програми за тією самою адресою витрачають той самий ліміт, тож API однаково може відповісти HTTP 429.
- **Час очікування відповіді фіксований** — 30 секунд на запит.

## Жива перевірка

На живому акаунті цей сервер ще ніхто не запускав (див. стан на початку). Зробити це можна командою `npm run live-check`: вона запускає зібраний сервер так, як це робить MCP-хост, прив’язаним до вашої філії, і викликає кожен інструмент читання з усіма його аргументами. Усе, що їй треба знати про філію (майстра, послугу, вільний день, слот), вона бере із самих відповідей. Кожна перевірка друкує один рядок — `PASS`, `FAIL` або `SKIP`, а код завершення дорівнює 1, якщо хоч одна не пройшла.

```bash
npm run live-check          # лише інструменти читання; нічого не створюється
npm run live-check:write    # те саме, а потім один тестовий запис, який одразу скасовується
```

Скрипт питає те, чого немає в середовищі:

| Що питає | Або задайте | Примітки |
| --- | --- | --- |
| партнерський токен | `ALTEGIO_PARTNER_TOKEN` | введення приховано |
| ідентифікатор філії | `ALTEGIO_LOCATION_ID` | |
| ідентифікатор форми запису | `ALTEGIO_FORM_ID` | число з адреси `https://bNNN.alteg.io`; Enter — `get_booking_form` не перевіряється. Цю змінну читає лише скрипт, сервер її не знає. |

Токен потрапляє до сервера через його середовище, тож його немає ні в команді, ні в історії оболонки, а з виводу його вичищено. У виводі — кількості й назви полів, а не імена ваших майстрів чи назви послуг.

Інструменту `get_booking` потрібен запис, створений через цю інтеграцію. Без `--write` його перевірено лише на вигаданому ідентифікаторі, який Altegio має відхилити.

**`live-check:write` змінює справжній розклад** і ніколи не запускається сам. Скрипт питає ваш власний телефон (введення приховано), показує обраний слот — останній вільний в останній вільний день — і чекає на `yes`. Потім створює запис для клієнта «MCP live check», читає його, скасовує і перевіряє, що запису більше немає. Altegio може сповістити бізнес і написати на цей телефон. У філії, де телефон підтверджують через SMS, скрипт ще надсилає код і питає його. Якщо скасувати не вдалося або це не вдалося підтвердити, останні рядки називають запис, який треба видалити вручну.

Без npm: `node scripts/live-check.mjs [--write]` після `npm run build`.

## Розробка

```bash
npm install
npm run lint          # tsc --noEmit для src/ і tests/
npm test              # збирає dist/ і тести, потім запускає їх через node:test
npm run spec:update   # оновлює знімок OpenAPI з developer.alteg.io
npm run live-check    # викликає кожен інструмент читання на справжньому API (питає токен)
```

- `src/endpoints.ts` — перелік методів API, які викликає сервер. `tests/spec.test.ts` порівнює його з `spec/altegio-api.snapshot.json` — скороченою копією офіційних описів OpenAPI (лише параметри, схеми запитів і вимоги до авторизації для цих методів) — і перевіряє, що кожен метод описано як доступний із самим лише партнерським токеном.
- Кожен тест інструмента викликає його через справжній MCP-клієнт. Коли тест завершується, кожен записаний у ньому запит проходить через `assertMatchesSpec`; ця функція звіряє шлях, параметри, заголовки й тіло запиту зі знімком. Єдине слабке місце — тіло `check_booking`: опис оголошує його елементи просто об’єктом, тому візит перевіряється через `create_booking`, який надсилає такий самий.
- `tests/e2e.test.ts` запускає зібраний сервер окремим процесом через stdio; замість API працює локальна HTTP-заглушка.
- `scripts/live-check.mjs` — це [жива перевірка](#жива-перевірка). `tests/live-check.test.ts` запускає її на локальній заглушці замість API, яка веде невелику філію, звіряє зі знімком кожен запит, що з цього виходить, і покриває випадки, де перевірка мусить не пройти, де нічого не можна створювати і де токен чи телефон не мають потрапити у вивід.
- Перевірити сервер уручну: `npx @modelcontextprotocol/inspector node dist/index.js`.

Сервер використовує офіційний TypeScript SDK ([`@modelcontextprotocol/server`](https://www.npmjs.com/package/@modelcontextprotocol/server)) і `zod`; інших залежностей для роботи він не має.

Будемо раді повідомленням про помилки та пул-реквестам. Про вразливості пишіть так, як описано в [SECURITY.md](SECURITY.md).
